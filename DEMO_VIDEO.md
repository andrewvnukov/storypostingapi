# Демо-видео для ревью TikTok

Ролик — главная причина отказов. Проверяют не качество съёмки, а то, что каждый
запрошенный scope виден в работе и что интерфейс ведёт себя по правилам.

Требования портала: mp4 или mov, до 5 файлов, **каждый до 50 МБ**, запись в
**песочнице** (приложение ещё не одобрено), домен в адресной строке совпадает с
Website URL из заявки.

---

## Часть 1. Подготовка — без неё снимать бессмысленно

### 1.1 Песочница и тестовый аккаунт

Вкладка **Песочница** рядом с «Производство» в шапке приложения.

- Создать песочницу, если её нет.
- Добавить туда свой TikTok-аккаунт как целевого пользователя (target user).
  Приглашение нужно принять в самом приложении TikTok — без этого авторизация
  вернёт ошибку, и вы потратите время на отладку вместо съёмки.
- Посмотреть **ключ и секрет клиента именно песочницы**. Если они отличаются от
  боевых — подставить их в `app/.env` на сервере и перезапустить:
  `docker compose up -d` (или `systemctl restart storypostingapi`).
- Redirect URI песочницы должен быть тот же: `https://<домен>/auth/callback`.

### 1.2 Проверить настройки заявки

- **Прямая публикация** включена — иначе `video.publish` недоступен и кнопка Publish
  работать не будет.
- Scope добавлены все шесть: `user.info.basic`, `user.info.profile`, `user.info.stats`,
  `video.list`, `video.upload`, `video.publish`.
- Продукты: Login Kit, Content Posting API, Display API.
- Нажато «Сохранять».

### 1.3 Подготовить контент

- Положить 2–3 фоновых клипа в `data/assets/backgrounds/` на сервере (или загрузить
  через форму в студии). Права на эти клипы должны быть ваши — они в кадре.
- Выбрать пост Reddit: без NSFW, 600–900 символов. Это примерно 40–60 секунд видео —
  достаточно, чтобы показать результат, и не настолько долго, чтобы ролик распух.
- Прогнать весь путь один раз **до записи**. Первый рендер всегда вскрывает мелочи:
  не хватило места на диске, не задан ключ TTS, фон короче видео.

### 1.4 Вернуть экран согласия

При повторном входе TikTok видит, что доступ уже выдан, и пропускает экран
подтверждения — возвращает сразу в приложение. В ролике этого кадра не будет, а
без него откажут. Два способа, применяйте оба:

1. **Отозвать доступ в TikTok.** Приложение TikTok → Профиль → ☰ → Настройки и
   конфиденциальность → Безопасность и разрешения → **Управление разрешениями
   приложений** → найти своё приложение → удалить доступ. Следующий вход пойдёт
   с полным экраном разрешений. Это работает всегда.
2. **Параметр `disable_auto_auth=1`** в ссылке авторизации. Приложение теперь
   добавляет его само (переменная `TIKTOK_DISABLE_AUTO_AUTH`, по умолчанию
   включена) — TikTok просят показывать страницу авторизации каждый раз, а не
   проскакивать её при живой сессии.

Между дублями повторяйте пункт 1: один раз выданный доступ снова начнёт
пропускать экран.

После аудита, если не хотите мучить реальных пользователей лишним экраном,
поставьте `TIKTOK_DISABLE_AUTO_AUTH=0` и перезапустите.

### 1.5 Подготовить запись

- Браузер на весь экран, адресная строка видна, масштаб 100%.
- Закрыть лишние вкладки и уведомления. В кадре не должно быть личной почты,
  менеджера паролей, других проектов.
- Курсор видим, движения медленные. Ревьюер должен успевать читать.
- Запись 1080p, 30 fps. Один проход без склеек внутри сценария.

## Часть 2. Сценарий

Удобно разбить на два файла — так каждый влезает в 50 МБ и ошибку в одном можно
переснять, не трогая второй.

### Файл 1 — вход и мониторинг (~1:30)

| # | Что в кадре | На что смотрит ревьюер |
|---|---|---|
| 1 | Открываете `https://<домен>/` с пустой адресной строки, набирая её руками | домен совпадает с Website URL из заявки |
| 2 | Жмёте **Connect TikTok** | |
| 3 | **Экран авторизации TikTok целиком**, виден список запрашиваемых разрешений. Задержитесь на нём 3–4 секунды, не прокручивая мимо | это обязательный кадр; его отсутствие — отказ |
| 4 | Подтверждаете, возвращаетесь в приложение. В шапке ник и аватар подключённого аккаунта | `user.info.basic` |
| 5 | Открываете страницу аккаунта: подписчики, лайки, число видео | `user.info.profile`, `user.info.stats` |
| 6 | Прокручиваете до плиток своих видео с просмотрами и лайками | `video.list` |

### Файл 2 — студия и публикация (~2:30)

| # | Что в кадре | На что смотрит ревьюер |
|---|---|---|
| 7 | Story studio: вставляете ссылку на пост Reddit, жмёте загрузку, появляется текст | |
| 8 | Правите текст, выбираете фон, голос, скорость, стиль субтитров, жмёте **Generate video** | что видео делает ваше приложение, а не загружается готовое |
| 9 | Экран превью: **видео играет прямо в браузере**, слышны озвучка и видны субтитры | |
| 10 | Экран настроек поста. Медленно: ник из Creator Info → выбор privacy level → переключатели комментариев/дуэтов/стичей, среди них неактивные → тумблер коммерческого контента → ссылка Music Usage Confirmation → галка AI-generated content | **это главный кадр ролика** |
| 11 | Выбираете **Only you (private)** | до аудита неаудированный клиент иначе и не опубликует |
| 12 | Жмёте **Publish**, переходите на страницу очереди, статус меняется на опубликовано | `video.publish` |
| 13 | Возвращаетесь на страницу настроек и показываете переключатель **Send to my TikTok drafts** | `video.upload` |
| 14 | Открываете TikTok, показываете опубликованный пост в профиле | полный цикл замкнулся |

Если черновики показывать не хотите — уберите `video.upload` из заявки. Сняли шаг 13 —
scope оставляете. Правило простое: что не показано, то не запрашивается.

### Про запланированную публикацию

Планировщик показывать не обязательно: для ревью важен сам вызов API, а он тот же.
Если хотите — на шаге 12 выберите «Publish on schedule», поставьте время через
две минуты и покажите, как запись в очереди сама переходит в опубликованную. Это
плюс к понятности, но ролик становится длиннее.

## Часть 3. Сжать до 50 МБ

Двухминутная запись 1080p с экрана — обычно 150–400 МБ. Сжимать так:

```bash
ffmpeg -i demo-raw.mp4 -vf "scale=1280:-2" -c:v libx264 -preset slow -crf 28 \
       -c:a aac -b:a 96k -movflags +faststart demo-1.mp4
ls -lh demo-1.mp4
```

1280 по ширине достаточно: интерфейс читается, вес падает втрое. Если всё ещё больше
50 МБ — поднимайте `-crf` до 30–32, дальше портится текст. Мельче 1280 не делайте,
подписи на экране настроек поста станут нечитаемыми, а это ровно то, что проверяют.

Проверить, что получилось:

```bash
ffprobe -v error -show_entries format=duration,size -show_entries stream=width,height demo-1.mp4
```

## Часть 4. Перед загрузкой

- [ ] Экран согласия TikTok виден целиком, а не мелькнул
- [ ] Каждый из шести scope встречается в кадре
- [ ] Экран настроек поста показан медленно и полностью
- [ ] Privacy level выбирается руками, а не стоит заранее
- [ ] Выбран Only you — до аудита иначе публикация не пройдёт
- [ ] Домен в адресной строке = Website URL из заявки
- [ ] Каждый файл до 50 МБ, формат mp4 или mov
- [ ] В кадре нет чужих вкладок, уведомлений и личных данных
- [ ] Внутри одного сценария нет склеек
